PROMPT TRIỂN KHAI MODULE MC1 - DỰ ÁN DSA QUẢN LÝ THƯ VIỆN
==========================================================

I. BỐI CẢNH DỰ ÁN
-----------------
Dự án: Hệ thống quản lý thư viện và mượn - trả tài liệu.
Ngôn ngữ: C++.
Phong cách code: OOP, sử dụng "using namespace std;" trong toàn bộ code C++.
Persistence đã hoàn thành trước đó, vì vậy module MC1 KHÔNG tự đọc file JSON trực tiếp.
Dữ liệu sách sau khi load từ Persistence được cung cấp dưới dạng vector<Book> hoặc cấu trúc tương đương.

MC1 là chức năng:
"Tra cứu chính xác một tài liệu theo book_id."

MC1 có:
- Baseline: Linear Search.
- Final Solution: Hash Table.
- Mode 1: So sánh Baseline và Final Solution trên CÙNG MỘT INPUT.
- Mode 2: Chỉ sử dụng Final Solution (Hash Table) để tìm và hiển thị kết quả.


II. YÊU CẦU CHÍNH CỦA MC1
--------------------------
Input:
- book_id do người dùng nhập.
Ví dụ:
B000123

Output:
- Nếu tìm thấy: trả về đúng Book có book_id tương ứng.
- Nếu không tồn tại: trả về nullptr hoặc thông báo "Book not found".

Access Pattern:
- Exact-key lookup.
- Một book_id chỉ tương ứng 0 hoặc 1 Book.

Yêu cầu correctness:
- Baseline và Final Solution phải nhận cùng book_id.
- Kết quả của hai phương án phải giống nhau.
- Nếu cả hai cùng tìm thấy cùng book_id => PASS.
- Nếu cả hai cùng không tìm thấy => PASS.
- Nếu kết quả khác nhau => FAIL.


III. BASELINE - LINEAR SEARCH
-----------------------------
Linear Search là phương án baseline.

Cách hoạt động:
- Duyệt tuần tự vector<Book>.
- Với mỗi Book, so sánh book.bookId với bookId cần tìm.
- Dừng ngay khi tìm thấy.
- Nếu duyệt hết mà không tìm thấy thì trả nullptr.

Yêu cầu Linear Search phải thu thập:
1. Book* kết quả.
2. Thời gian thực thi tìm kiếm.
3. Số lần so sánh book_id.
4. Tên phương pháp: "Linear Search".
5. Big-O: O(n).

Độ phức tạp:
- Best case: O(1).
- Average: O(n).
- Worst case: O(n).
- Khi hiển thị benchmark có thể dùng O(n) để mô tả chính.


IV. FINAL SOLUTION - HASH TABLE
-------------------------------
Final Solution của MC1 là Hash Table.

Mục tiêu:
book_id -> Book*

Hash Table phải:
- Tự cài đặt.
- Không sử dụng unordered_map để thay thế logic Hash Table.
- Có hashFunction().
- Có insert().
- Có search().
- Có cơ chế xử lý collision.

Cơ chế collision đề xuất:
- Separate Chaining.
- Mỗi bucket chứa một linked list HashNode.

HashNode tối thiểu:
- string key
- Book* book
- HashNode* next

Yêu cầu Hash Table search phải thu thập:
1. Book* kết quả.
2. Thời gian thực thi search.
3. Số key/node đã so sánh trong bucket.
4. Tên phương pháp: "Hash Table".
5. Big-O:
   - O(1) average.
   - O(n) worst case.

Lưu ý:
- Chỉ đo thời gian search.
- KHÔNG cộng thời gian build Hash Table vào search time khi so với Linear Search.
- Hash Table được build một lần sau khi Persistence load books.


V. MODE 1 - COMPARISON MODE
---------------------------
Mode 1 dùng để so sánh Baseline và Final Solution.

Hai phương án bắt buộc:
- Nhận cùng book_id.
- Chạy trên cùng vector<Book>.
- Trả kết quả dưới cùng một kiểu dữ liệu SearchResult.

Các tiêu chí cần so sánh:

1. KẾT QUẢ TRẢ VỀ CÓ GIỐNG NHAU KHÔNG
- So sánh book_id của kết quả.
- Nếu cả hai nullptr => PASS.
- Nếu cả hai có Book và cùng bookId => PASS.
- Trường hợp khác => FAIL.

2. THỜI GIAN THỰC THI
- Dùng chrono.
- Đơn vị khuyến nghị: nanoseconds.
- Chỉ đo thời gian search của từng phương án.

3. SỐ LẦN SO SÁNH
- Linear Search:
  số lần kiểm tra book.bookId == bookId.
- Hash Table:
  số HashNode/key được kiểm tra trong bucket sau khi hash.

4. ĐỘ PHỨC TẠP THUẬT TOÁN
- Linear Search:
  Best O(1), Average O(n), Worst O(n).
- Hash Table:
  Average O(1), Worst O(n).

5. BIG-O
- Gộp cùng phần độ phức tạp khi hiển thị.
- Linear Search: O(n).
- Hash Table: O(1) average, O(n) worst case.

6. TRADE-OFF TỐC ĐỘ VÀ BỘ NHỚ
Không cần đo RAM chính xác.
Chỉ cần giải thích:

Linear Search:
+ Không cần cấu trúc index phụ.
+ Ít bộ nhớ phụ hơn.
- Tìm kiếm chậm hơn khi dữ liệu lớn.
- Search O(n).

Hash Table:
+ Tìm kiếm trung bình nhanh hơn.
+ Search O(1) average.
- Cần thêm bộ nhớ cho buckets, HashNode và con trỏ.
- Có collision và cần cơ chế xử lý collision.

Output Mode 1 nên có dạng:

=================================
        MC1 COMPARISON
=================================

BASELINE
---------------------------------

FINAL SOLUTION
---------------------------------

Comparisons : ...
Big-O       : O(1) average

VALIDATION
---------------------------------
Same Result : PASS

TRADE-OFF
---------------------------------
Linear Search:
+ Less additional memory
- Slower lookup when dataset grows

Hash Table:
+ Faster average lookup
- Uses additional memory for buckets and HashNodes
