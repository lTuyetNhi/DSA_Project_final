============================================================
PHẦN A - RQ1: TRA CỨU TẤT CẢ TÀI LIỆU THEO THỂ LOẠI
============================================================

I. BỐI CẢNH RQ1
---------------
RQ1:
"Tra cứu tất cả tài liệu theo thể loại."

Baseline:
Linear Scan toàn bộ danh sách Book.

Final Solution:
Category Hash Table.

Mapping:
category -> vector<Book*>

RQ1 là truy vấn một-nhiều:
1 category -> 0, 1 hoặc nhiều Book.

Ví dụ:

B001 -> CNTT
B002 -> KinhTe
B003 -> CNTT
B004 -> VanHoc
B005 -> CNTT

Input:
CNTT

Output:
B001
B003
B005

RQ1 phải trả TẤT CẢ Book thuộc category.
Không được dừng sau Book đầu tiên.


II. INPUT / OUTPUT
------------------
Input:
string category

Ví dụ:
CNTT

Output:
vector<Book*> chứa tất cả Book thuộc category.

Nếu không có Book:
- trả vector rỗng.
- Result Count = 0.


III. BASELINE - LINEAR CATEGORY SCAN
-----------------------------------
Class đề xuất:
LinearCategoryScan

Cách hoạt động:
1. Nhận vector<Book>& books.
2. Nhận const string& category.
3. Duyệt toàn bộ books.
4. Với mỗi Book:
   kiểm tra:
   book.category == category
5. Nếu đúng:
   push_back(&book) vào result.
6. Không dừng sớm.
7. Trả CategoryResult.

Baseline phải thu thập:
- vector<Book*> books
- executionTime
- comparisons
- method
- bigO

method:
"Linear Scan"

bigO:
"O(n)"

comparisons:
số lần kiểm tra category.

Độ phức tạp:
O(n)


IV. FINAL SOLUTION - CATEGORY HASH TABLE
----------------------------------------
Class đề xuất:
CategoryHashTable

Mục tiêu:
Dùng category làm key để tìm trực tiếp nhóm Book.

Mapping:
category -> vector<Book*>

Hash node đề xuất:

struct CategoryHashNode {
    string category;
    vector<Book*> books;
    CategoryHashNode* next;
};

CategoryHashTable phải có:
- constructor
- destructor
- hashFunction()
- insert(Book*)
- build(vector<Book>&)
- search(const string& category)
- collision handling

Collision:
Separate Chaining.

Không dùng unordered_map để thay toàn bộ logic Hash Table nếu yêu cầu môn học là tự cài DSA.

Luồng search:

category
  ->
hashFunction()
  ->
bucket
  ->
CategoryHashNode
  ->
vector<Book*>


V. BIG-O RQ1
------------
Baseline:
Linear Scan
O(n)

Final:
Tìm category:
O(1) average

Liệt kê k Book:
O(k)

Tổng:
O(1 + k) average

Trong đó:
n = tổng số Book.
k = số Book thực sự thuộc category.

Không được ghi Final là O(1) hoàn toàn vì vẫn phải trả k kết quả.

------------------------

X. TRADE-OFF RQ1
----------------
Linear Scan:

Ưu:
- Không cần index phụ.
- Ít bộ nhớ phụ.
- Cài đặt đơn giản.

Nhược:
- Mỗi query phải scan toàn bộ books.
- O(n).

Category Hash:

Ưu:
- Tìm đúng category nhanh hơn.
- O(1 + k) average.
- Phù hợp với query category thường xuyên.

Nhược:
- Tốn thêm memory.
- Cần lưu HashNode và vector<Book*>.
- Khi thêm/xóa/đổi category phải cập nhật index.
- Có thể lệch dữ liệu nếu index không được đồng bộ đúng.

PHẦN B - RQ2: THEO DÕI TÀI LIỆU ĐANG MƯỢN VÀ QUÁ HẠN
============================================================

I. BỐI CẢNH RQ2
---------------
RQ2:
"Theo dõi tài liệu đang được mượn và tài liệu quá hạn."

Baseline:
Linear Scan.

Final Solution:
Balanced BST / AVL Tree theo dueDate.

Dữ liệu:
vector<BorrowRecord>

Điều kiện overdue:

status == "BORROWING"
AND
dueDate < currentDate


II. INPUT / OUTPUT
------------------
Input:
currentDate

Format:
YYYY-MM-DD

Ví dụ:
2026-10-02

Output:
tất cả BorrowRecord quá hạn.


III. BASELINE - LINEAR OVERDUE SCAN
-----------------------------------
Class đề xuất:
LinearOverdueScan

Cách hoạt động:
1. Nhận vector<BorrowRecord>&.
2. Nhận currentDate.
3. Duyệt toàn bộ records.
4. Với mỗi record:
   kiểm tra status.
   kiểm tra dueDate.
5. Nếu:
   status == "BORROWING"
   AND
   dueDate < currentDate
   thì thêm BorrowRecord* vào result.
6. Trả OverdueResult.

Baseline phải thu thập:
- vector<BorrowRecord*> records
- executionTime
- checks
- method
- bigO

method:
"Linear Scan"

bigO:
"O(n)"

Độ phức tạp:
O(n)


IV. FINAL SOLUTION - AVL TREE
-----------------------------
Class đề xuất:
AVLTree

Key:
dueDate

Vì nhiều BorrowRecord có thể có cùng dueDate,
mỗi AVL node nên chứa một nhóm records.

Node đề xuất:

struct AVLNode {
    string dueDate;
    vector<BorrowRecord*> records;

    AVLNode* left;
    AVLNode* right;

    int height;
};

AVL Tree phải có:
- insert()
- remove() nếu cần
- rotateLeft()
- rotateRight()
- getBalance()
- updateHeight()
- build()
- findOverdue()
- range query


V. RANGE QUERY
--------------
Mục tiêu:

dueDate < currentDate

và:
status == BORROWING

Final không được pop/xóa record chỉ để xem overdue.

Cây phải:
- duyệt có thứ tự.
- cắt nhánh khi có thể.
- chỉ truy cập vùng ngày cần thiết.


VI. BIG-O RQ2
-------------
Baseline:
O(n)

Final:
O(log n + k)

Trong đó:
n = số record.
k = số BorrowRecord quá hạn trả về.

Insert:
O(log n)

Delete:
O(log n)

PHẦN C - RQ3: TRA CỨU / TÌM KIẾM TÀI LIỆU THEO TÊN SÁCH
============================================================

I. BỐI CẢNH RQ3
---------------
Theo báo cáo hiện tại:

RQ3:
"Tra cứu và tìm kiếm tài liệu theo tên sách hoặc từ khóa."

Baseline:
Linear Scan toàn bộ thư viện + String Matching.

Final Solution:
Tận dụng Category Hash Table của RQ1
+
String Matching cục bộ trong category.

KHÔNG tạo thêm một Title Hash Table độc lập.

Mục tiêu:
- giảm memory phụ.
- tránh duy trì bảng hash thứ ba.
- linh hoạt với partial keyword.
- thu hẹp phạm vi tìm kiếm trước khi string matching.


II. LƯU Ý QUAN TRỌNG VỀ INPUT
-----------------------------
Báo cáo hiện tại mô tả:
- người dùng tìm theo tên/từ khóa.
- Final Solution tận dụng Category Hash để thu hẹp nhóm rồi lọc chuỗi.

Vì vậy để triển khai đúng Final Solution hiện tại,
nên dùng input:

category
keyword

Ví dụ:

Category:
CNTT

Keyword:
data

Nếu nhóm muốn RQ3 chỉ nhập keyword mà không chọn category,
cần chốt lại thiết kế vì báo cáo chưa mô tả rõ cách xác định category chỉ từ keyword.


III. STRING MATCHING
--------------------
RQ3 phải hỗ trợ:
- exact title.
hoặc
- partial keyword.

Ví dụ:

Title:
"Data Structures and Algorithms"

Keyword:
"data"

=> MATCH

Đề xuất:
case-insensitive.

Có thể:
- chuyển title về lowercase.
- chuyển keyword về lowercase.
- dùng cùng một hàm string matching cho Baseline và Final.

Không được để Baseline và Final dùng quy tắc matching khác nhau.


IV. BASELINE - FULL LINEAR TITLE SCAN
------------------------------------
Class đề xuất:
LinearTitleScan

Nếu benchmark dùng category + keyword,
Baseline phải dùng cùng điều kiện:

book.category == inputCategory

AND

title matches keyword

Nhưng vẫn phải scan toàn bộ vector<Book>.

Cách hoạt động:
1. Duyệt toàn bộ books.
2. Tăng booksChecked.
3. Kiểm tra category.
4. Nếu category đúng:
   kiểm tra title với keyword.
5. Nếu match:
   thêm Book* vào result.

Baseline phải thu thập:
- vector<Book*> books
- executionTime
- booksChecked
- method
- bigO

method:
"Full Linear Title Scan"

bigO:
"O(n) + string matching"


V. FINAL SOLUTION - CATEGORY HASH + STRING MATCHING
---------------------------------------------------
Class đề xuất:
CategoryTitleSearch

Final Solution không build Title Hash thứ ba.

Luồng:

category
  ->
CategoryHashTable.search(category)
  ->
vector<Book*> trong category
  ->
lọc title theo keyword
  ->
vector<Book*> kết quả

CategoryTitleSearch nên sử dụng CategoryHashTable đã có của RQ1.

Không nên build một CategoryHashTable mới riêng cho RQ3 nếu mục tiêu kiến trúc là tái sử dụng cùng index.


VI. CHIA SẺ CATEGORY HASH VỚI RQ1
---------------------------------
Đề xuất:

RQ1
  |
  v
CategoryHashTable
  ^
  |
RQ3

Hoặc:

RQ3(CategoryHashTable& categoryIndex)

Trong RQ3:
- giữ reference đến CategoryHashTable của RQ1.
- không rebuild index riêng.


VII. BIG-O RQ3
--------------
Baseline:

Full scan:
O(n)
+
string matching cost

Có thể mô tả:
O(n * m)

n = số Book
m = chi phí string matching tương đối

Final:

Hash category:
O(1) average

Lọc k Book trong category:
O(k * m)

Có thể mô tả đơn giản trong UI:
O(1 + k) average + string matching

Không được ghi Final là O(1) hoàn toàn.

PHẦN E - MỤC TIÊU CUỐI CÙNG
============================================================

RQ1
---
Baseline:
Linear Scan
O(n)

Final:
Category Hash
O(1 + k) average

So sánh:
- Same Count
- Same Result Set
- Time
- Comparisons
- Big-O
- Trade-off


RQ2
---
Baseline:
Linear Scan
O(n)

Final:
AVL Tree
O(log n + k)

So sánh:
- Same Count
- Same Result Set
- Time
- Checks / Nodes Visited
- Big-O
- Trade-off


RQ3
---
Baseline:
Full Linear Title Scan

Final:
Category Hash + String Matching

So sánh:
- Same Count
- Same Result Set
- Time
- Books Checked
- Big-O
- Trade-off

RQ3 theo báo cáo hiện tại KHÔNG phải Queue/Waitlist.
RQ3 là tìm kiếm tài liệu theo tên sách / từ khóa.

Nếu nhóm muốn thay đổi RQ3 thành chức năng khác,
phải cập nhật lại báo cáo và kiến trúc để tránh lệch giữa code và tài liệu.
