PHẦN B - TRIỂN KHAI CHI TIẾT MODULE MC2
====================================================

PROMPT TRIỂN KHAI MODULE MC2 - DỰ ÁN DSA QUẢN LÝ THƯ VIỆN
==========================================================

I. BỐI CẢNH DỰ ÁN
-----------------
Dự án: Hệ thống quản lý thư viện và mượn - trả tài liệu.
Ngôn ngữ: C++.
Phong cách code: OOP, sử dụng "using namespace std;" trong toàn bộ code C++.
Persistence đã hoàn thành trước đó, vì vậy module MC2 KHÔNG tự đọc file JSON trực tiếp.
Dữ liệu sách sau khi load từ Persistence được cung cấp dưới dạng vector<Book> hoặc cấu trúc tương đương.

MC2 là chức năng:
"Tìm tài liệu có borrowCount cao nhất."

MC2 có:
- Baseline: Linear Scan tìm max.
- Final Solution: Max-Heap.
- Mode 1: So sánh Baseline và Final Solution trên CÙNG MỘT DATASET.
- Mode 2: Chỉ sử dụng Final Solution (Max-Heap) để lấy và hiển thị kết quả.


II. YÊU CẦU CHÍNH CỦA MC2
--------------------------
Input chính:
- vector<Book>

Mỗi Book tối thiểu có:
- string bookId
- string title
- int borrowCount

Output:
- Book có borrowCount lớn nhất.

Ví dụ:
B001 -> 50
B002 -> 120
B003 -> 80

Kết quả:
B002 -> 120


III. QUY TẮC TIE-BREAK
----------------------
Nếu nhiều Book có cùng borrowCount cao nhất thì phải dùng cùng một quy tắc cho cả Baseline và Final Solution.

Đề xuất:
- borrowCount lớn hơn được ưu tiên.
- Nếu borrowCount bằng nhau thì bookId nhỏ hơn được ưu tiên.

Ví dụ:
B001 -> 100
B002 -> 100

Kết quả:
B001 được ưu tiên.

Comparator của Linear Scan và Max-Heap phải giống nhau để đảm bảo kết quả so sánh là hợp lệ.


IV. BASELINE - LINEAR MAX SCAN
------------------------------
Baseline của MC2 là Linear Scan tìm max.

Cách hoạt động:
- Nếu vector<Book> rỗng: trả nullptr.
- Chọn Book đầu tiên làm max hiện tại.
- Duyệt toàn bộ Book.
- So sánh borrowCount với max hiện tại.
- Nếu lớn hơn thì cập nhật max.
- Nếu bằng nhau thì áp dụng tie-break bằng bookId.

Yêu cầu Baseline phải thu thập:
1. Book* kết quả.
2. Thời gian thực thi.
3. Số lần so sánh.
4. Tên phương pháp: "Linear Max Scan".
5. Big-O: O(n).

Độ phức tạp:
- Get max: O(n).

Lý do:
Muốn chắc chắn Book nào có borrowCount lớn nhất thì phải duyệt toàn bộ dataset.


V. FINAL SOLUTION - MAX-HEAP
----------------------------
Final Solution của MC2 là Max-Heap.

Mục tiêu:
- Root luôn là Book có borrowCount cao nhất.

Max-Heap phải:
- Tự cài đặt.
- Không dùng priority_queue của STL để thay thế logic Heap.
- Có comparator riêng.
- Có build().
- Có insert().
- Có getMax().
- Có heapifyUp().
- Có heapifyDown().
- Có updateBorrowCount() nếu module hỗ trợ update.

Heap nên lưu:
- Book*
hoặc reference tương đương để tránh copy dữ liệu Book không cần thiết.

Comparator:
1. borrowCount cao hơn -> ưu tiên cao hơn.
2. Nếu bằng nhau -> bookId nhỏ hơn -> ưu tiên cao hơn.

Độ phức tạp:
- build heap bottom-up: O(n).
- getMax(): O(1).
- insert(): O(log n).
- update borrowCount: O(log n) khi cần heapifyUp/heapifyDown.


VI. MODE 1 - COMPARISON MODE
----------------------------
Mode 1 dùng để so sánh:
- Baseline: Linear Max Scan
- Final Solution: Max-Heap

Hai phương án bắt buộc:
- Chạy trên cùng vector<Book>.
- Chạy trên cùng trạng thái dữ liệu.
- Dùng cùng comparator và tie-break.

Các tiêu chí cần so sánh:

1. KẾT QUẢ TRẢ VỀ CÓ GIỐNG NHAU KHÔNG
- So sánh bookId.
- So sánh borrowCount.
- Nếu cả hai nullptr => PASS.
- Nếu cả hai có Book và cùng bookId + borrowCount => PASS.
- Trường hợp khác => FAIL.

2. THỜI GIAN THỰC THI
- Dùng chrono.
- Đơn vị khuyến nghị: nanoseconds.
- Baseline đo thời gian findMax().
- Final Solution đo thời gian getMax().
- KHÔNG cộng thời gian build Heap vào getMax time khi benchmark trực tiếp thao tác lấy max.

3. SỐ LẦN SO SÁNH / SỐ BƯỚC
- Baseline:
  đếm số lần so sánh Book với max hiện tại.
- Max-Heap getMax:
  root đã là max, có thể xem là 1 bước truy xuất.
- Nếu benchmark update:
  đếm comparison hoặc số bước trong heapifyUp/heapifyDown.

4. ĐỘ PHỨC TẠP THUẬT TOÁN
- Linear Max Scan: O(n).
- MaxHeap getMax: O(1).
- MaxHeap update: O(log n).
- MaxHeap build: O(n).

5. BIG-O
Có thể gộp cùng phần độ phức tạp khi hiển thị:
- Baseline: O(n).
- Final getMax: O(1).
- Final update: O(log n).

6. TRADE-OFF TỐC ĐỘ VÀ BỘ NHỚ
Không cần đo RAM chính xác.
Chỉ cần giải thích:

Linear Scan:
+ Không cần cấu trúc phụ để tìm max.
+ Ít bộ nhớ phụ.
- Mỗi lần tìm max phải quét toàn bộ dataset.
- Get max O(n).

Max-Heap:
+ getMax O(1).
+ update O(log n).
- Cần thêm bộ nhớ để lưu Heap.
- Phải duy trì Heap đồng bộ với dữ liệu Book.
- Code phức tạp hơn Linear Scan.


VII. TEST A - GET MAX
---------------------
Đây là benchmark bắt buộc của MC2.

Baseline:
LinearMaxScan.findMax()

Final:
MaxHeap.getMax()
